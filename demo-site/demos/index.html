Install from source

Development installs require Node.js 18+ and Go 1.24+. The install script builds the CLI and daemon for this machine.

Clone the repository, install the package globally, then run setup. The npm package name in the repo is ownbot. Use the ownbot command throughout.

git clone https://github.com/TaxCollector23/OwnBot.git
cd OwnBot
npm install -g . --allow-scripts=ownbot
ownbot setup

The npm package is not published yet as a stable release. After publication, the alpha install will be:

npm install -g ownbot@alpha
Setup does not download models and does not collect hosted provider API keys. Install a local runtime first if no model is detected.

Choose a local model

Setup detects installed models exposed by Ollama, LM Studio, llama.cpp, or vLLM. It probes the model, then creates a text-only agent with no tools enabled.

Run interactive setup:

ownbot setup

For a known installed model, use headless setup:

ownbot setup --yes --model MODEL_ID

If no model appears, install and start a local runtime, download a model you choose, then run setup again. A config file is available for unattended setup with custom names or prompts.

What setup creates

  • A saved local model endpoint and probe result
  • A disabled or text-only agent with no tools until you enable capabilities
  • Daemon state under ~/.ownbot/ (or your --data-dir)

Open the dashboard after setup:

open http://127.0.0.1:8765/dashboard

The local API token

The daemon creates its local API token automatically under ~/.ownbot/api.token.

That token protects the host’s daemon API. It is not a model-provider key. The CLI reads it from the host state directory; you do not create or copy it for normal CLI setup.

  • Default data directory: ~/.ownbot/
  • Token file: api.token
  • Common CLI flag: --url URL (default http://127.0.0.1:8765)
  • Common CLI flag: --data-dir DIR
Keep the token on the host. Owner links and pairing flows are designed so the API token itself is not placed in shared URLs.

Use over SSH

Install ownbot on the host, run setup there, and start the daemon from the SSH session. The host keeps its state and token locally.

ssh user@host
cd OwnBot
ownbot setup
ownbot daemon start

In SSH sessions, if the CLI cannot open a browser, it prints a short-lived owner link and an SSH tunnel command. Keep the tunnel open, then open that link on your laptop before it expires. The link uses a one-time ticket; it does not contain the API token.

Notes

  • The token remains on the host.
  • Re-running ownbot daemon start can create a fresh owner session for an already-running daemon.
  • For LAN pairing from another device on the same private network, use the LAN guide below instead of exposing the host publicly.

LAN access

LAN mode exposes the dashboard to devices on the host’s private Wi‑Fi or Ethernet over HTTPS. Cellular and public internet access are not supported.

The daemon binds one detected private IP on port 8766. It does not bind a public interface or create a router port-forward.

ownbot daemon start --lan

If the daemon is already running without LAN access:

ownbot daemon stop
ownbot daemon start --lan

Choose an explicit private address when automatic selection is wrong:

ownbot daemon start --lan --lan-address 192.168.1.25:8766

Certificate trust

The LAN HTTPS certificate is self-signed. Compare the printed SHA-256 fingerprint with the host before trusting it. You can compute the fingerprint independently:

openssl x509 -in ~/.ownbot/lan.cert.pem -noout -fingerprint -sha256

Transfer only lan.cert.pem over a method you trust. Never share lan.key.pem.

Pair and revoke

  1. Start LAN mode and open the local dashboard with an owner session.
  2. Run ownbot daemon pair on the host and send the one-use pairing link only to the intended device.
  3. Open the HTTPS link on that device and submit a device name.
  4. Revoke later with ownbot daemon devices --revoke DEVICE_ID.
Paired devices get dashboard access but cannot view LAN settings, create links, or manage other devices. Full steps live in the LAN access guide.

Daemon service

ownbot daemon install registers the daemon for the current account and starts it now. It does not request administrator access.

ownbot daemon status
ownbot daemon install
ownbot daemon uninstall
  • macOS: ~/Library/LaunchAgents/com.ownbot.daemon.plist
  • Linux: systemd --user unit under ~/.config/systemd/user/ownbot.service

Pass the same --config, --listen, --data-dir, --lan, and --lan-address options used to start the daemon. Uninstall stops and removes the service definition but keeps state, tokens, models, agents, and audit data.

Hardware and model checks

Use ownbot inspect hardware for host CPU architecture, RAM totals, GPU/VRAM telemetry when available, and discovered local models.

ownbot inspect hardware
ownbot inspect hardware --benchmark
ownbot inspect hardware --benchmark --model MODEL_NAME

Benchmark mode runs the daemon’s capability probe against configured local models also found in the provider’s installed-model list. It records probe latency. No models are downloaded and no hosted provider key is used.

Ollama 0.40.12 qwen3:1.7b (Q4_K_M) 4/4 44.0s 1.92 GiB

These timings came from separate GitHub-hosted Linux CPU runners and cannot rank the runtimes against each other. Always probe the installed model on the target host. Details: hardware.md.

Inspect local setup and audit history

Use ownbot inspect check to review daemon, model, agent, tool, and MCP metadata plus pending approvals. Use ownbot inspect audit export to read saved audit events.

These read-only commands do not install models, run agent tasks, or prove a live model or provider will respond. See the inspect and audit guide for verified options, output behavior, and safe bug-report details.

Homebrew

Homebrew builds both ownbot and ownbotd from the latest main source. Go is a build dependency; no prebuilt bottle is provided.

brew tap TaxCollector23/ownbot https://github.com/TaxCollector23/OwnBot
brew install --HEAD taxcollector23/ownbot/ownbot

This is a moving --HEAD install, not a stable release. Rebuild from latest main with:

brew upgrade --fetch-HEAD taxcollector23/ownbot/ownbot

Installing the formula does not start or register a service. Use ownbot daemon install for per-user login services on macOS and Linux.

Release status

Updated 2026-10-28. ownbot is still in development. Do not treat the checkout as a signed or production release.

Current scope

  • CLI supports local model detection and capability probing, daemon controls, and a local dashboard.
  • Setup detects Ollama, LM Studio, llama.cpp, and vLLM. It does not download models or configure hosted provider keys.
  • LAN mode provides HTTPS pairing on the host’s private network only.
  • macOS and Linux user-level service management is implemented; verify it on the target machine before relying on it unattended.

Verified evidence

  • Native Go tests passed on macOS, Linux, and Windows; FreeBSD binaries cross-built in CI.
  • Isolated two-container LAN lab passed pairing, replay, revocation, and restart persistence checks.
  • Disposable local npm tarball install verified SSH owner-link redemption, replay rejection, daemon inspection, and shutdown with a service-manager stub.
  • Ollama and llama.cpp each passed all four real capability checks on hosted CPU runners.

Full notes: STATUS.md. Upstream docs site: GitHub Pages.
