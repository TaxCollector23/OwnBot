# Sandbox, terminal, dashboard, and explainer verification

The terminal now lists five root commands, numbers setup steps, and uses blue headings only on interactive terminals. Non-TTY output, NO_COLOR, TERM=dumb, and JSON stay unstyled. The dashboard has a clearer task composer, readable status, responsive history, and refreshed results after approval resumes a run.

The deterministic test model is `ownbot-sandbox-fake-v1`. It runs no weights and supports probe replies, namespaced MCP tool requests, and a final scripted summary. The interactive launcher isolates its daemon, credentials, logs, and fixture services in disposable state. It does not use a real provider or account.

Verified:

- [Native CI on a3de610](https://github.com/TaxCollector23/OwnBot/actions/runs/41768201562): Linux, macOS, Windows tests/workflow checks, FreeBSD cross-build, and npm dry run passed. FreeBSD runtime and public npm installation remain unverified.
- [Dashboard browser CI on a3de610](https://github.com/TaxCollector23/OwnBot/actions/runs/41768201581): passed all 18 cases.
- [Virtual sandbox](https://github.com/TaxCollector23/OwnBot/actions/runs/41768144145): fixture smoke test and 60 real CLI/daemon workflow checks passed.
- Local actual dashboard flow: task request, zero pending writes, exactly one write after approval, and no mobile horizontal overflow passed. Desktop and phone screenshots were inspected. No local model was installed.
- Full local recording walkthrough passed. It records the real docs, actual CLI help, diagrams, and a real daemon approval flow with the simulated model. Narration uses the public script and Microsoft's online Aria neural speech service, without a key or local weights.

Fixes found during verification: old CLI wording assertions were updated; browser CI was pinned to Ubuntu 24.04 for Playwright compatibility; the scripted model now returns the namespaced tool name; the recording agent now saves its required system prompt; post-approval results now refresh; recording shows requested arguments and checks matching approval, dispatch, and success audit events.

The local FFmpeg build lacks the subtitles/libass filter. Final caption rendering therefore runs in the disposable Linux recording VM. The replay and renderer are in `demo-site/scripts/explainer/`; skill references and voice scope are documented there. Recordings and credentials are excluded from Git. No recording is embedded in the documentation site.

Live-account integration, real model quality/performance, physical pairing, target service installation, and signed release qualification remain outside these results.
