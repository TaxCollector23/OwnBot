Install

The v0.1.0-alpha.4 GitHub prerelease provides CLI and daemon archives for manual testing. Verify the SHA-256 checksum file before running an archive. The alpha artifacts are unsigned and are not a production release. The npm package is not published yet, so npm install -g ownbot is not available.

For a development install from source on macOS or Linux, build the CLI and daemon with Go 1.24 or newer:

git clone https://github.com/TaxCollector23/OwnBot.git
cd OwnBot
mkdir -p bin
go build -o bin/ownbot ./cmd/ownbot
go build -o bin/ownbotd ./cmd/ownbotd
./bin/ownbot setup

See the first-run guide for prerequisites and current release status.

First-run setup

Interactive setup detects Ollama, LM Studio, Jan, llama.cpp, and vLLM local endpoints. It shows available memory and storage, recommends a shortlist model when resource readings support a fit estimate, and can download an Ollama or LM Studio choice. Jan downloads remain in Jan Hub.

ownbot setup

Every selected model must pass OwnBot's capability probe before setup creates the agent. The permissions review starts with no tools selected; runtime policy and approvals still apply to selected tools.

For an installed model in a non-interactive terminal, supply its local provider, endpoint, and model explicitly:

ownbot setup --yes \
  --provider ollama \
  --base-url http://127.0.0.1:11434/v1 \
  --model qwen3:1.7b

A config file supports custom names and prompts. With the default daemon URL, successful setup enables LAN access and prints a one-use pairing QR. See the first-run guide for runtime, download, and permission details.

The local API token

The daemon creates its local API token automatically under ~/.ownbot/api.token. It protects the host's daemon API and is not a model-provider key. The CLI reads it from the host state directory; you do not create or copy it for CLI setup.

Use over SSH

Connect to the host, install ownbot there, then run setup and start the daemon from that SSH session. The host keeps its state and token locally.

ssh user@host
cd OwnBot
ownbot setup
ownbot daemon start

In SSH sessions, the CLI prints a short-lived owner link and an SSH tunnel command instead of opening the host’s browser. Keep the tunnel open and open the printed link on your laptop. The link uses a one-time ticket; it does not contain the API token.

Access from another device

Interactive setup starts LAN mode and prints a one-use pairing QR after the selected model passes its probe. To start LAN access manually for a device on the same private Wi-Fi or Ethernet:

ownbot daemon start --lan

LAN access stays on the private network. OwnBot does not provide cellular/public access, a relay, or router port-forwarding. LAN HTTPS uses the host-local certificate in ~/.ownbot/lan.cert.cer; the unsigned iOS profile is ~/.ownbot/lan.cert.mobileconfig. Compare the SHA-256 fingerprint printed by OwnBot before installing either certificate. On iPhone or iPad, enable full trust in Certificate Trust Settings. On Android, install the certificate as a CA. If the browser still reports a certificate warning, do not continue or enter the pairing link. Real phone trust and pairing remain unverified; see the LAN guide.

The one-use QR link does not contain the host API token. For later pairing, run ownbot daemon pair. Revoke a device with ownbot daemon devices --revoke DEVICE_ID.
